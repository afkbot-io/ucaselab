# Проверки приложения

## Быстрые проверки

`make test` запускает pytest, Ruff, mypy, проверку документации, строгую сборку TypeScript и проверку типов самих UI-тестов. Требуется локальный PostgreSQL с применёнными миграциями. Unit/integration-тесты работают в откатываемых транзакциях.

Для отчёта покрытия:

```bash
uv run --frozen pytest -q --cov=app --cov-branch --cov-report=term-missing
```

CI проверяет ветки Python и удерживает покрытие не ниже 85%. Покрытие строк не доказывает корректность продукта: отдельно проверяются права, неизменяемость снимков, конфликтующие записи, границы проектов, работа MCP и браузерные сценарии.

## Браузерные проверки

```bash
npm ci --prefix apps/web
cd apps/web
npx playwright install --with-deps chromium firefox webkit
cd ../..
make test-ui
```

Playwright собирает frontend, запускает Vite preview на 4173 с теми же заголовками CSP, что у production nginx, и API на 18017. Эти порты должны быть свободны. Существующий backend на 8017 и интерфейс на 5173 не используются. `scripts/run_e2e_api.py` создаёт случайную схему `ucaselab_e2e_*` в development PostgreSQL, применяет все миграции, создаёт временное файловое хранилище и удаляет свою схему после остановки. Production-режим запрещён. Не направляйте тесты на production-базу.

Пять синтетических пользователей создаются обычной регистрацией. Членство назначается обычными приглашениями. Каждый сценарий получает отдельный проект; тестовых обходов авторизации в приложении нет. Письма не отправляются. После прерванного аварийным завершением процесса прогона может остаться временная схема; удаляйте только схему с подтверждённым UUID этого запуска.

Матрица: Chromium на широком экране, мобильный Chromium 390 px, WebKit и обзор разделов в Firefox. Дополнительный сценарий проверяет страницы на 320, 390, 768 и 1024 px. Таблицы при необходимости прокручиваются внутри своего контейнера; страница не должна переполнять экран.

Проверяются регистрация/вход/выход, создание и переключение проектов, редактор/публикация/история кейсов, обсуждения, папки, спецификации и связи, аккаунты/секреты, планы, подготовка и проведение прогонов, четыре вида результата, отчёты, роли, уведомления, MCP-токены и темы. Axe проверяет доступность всех разделов, форм токенов и тёмной темы по WCAG 2 A/AA и 2.1 AA. Автоматическая проверка не заменяет оценку понятности текста и визуального вида.

Артефакты: `output/playwright/e2e/report`, `results.json`, снимки и traces неудачных проверок в `results`. `npm run test:ui:report --prefix apps/web` открывает отчёт. В `auth` сохраняются только локальные синтетические сессии с правами 0600; каталог не включается в git, CI-артефакты или релиз.

Для одного браузера:

```bash
npm run test:ui --prefix apps/web -- --project=desktop-chromium
```

CI запускает ту же матрицу без автоматических повторов и сохраняет отчёт даже при ошибке.

Дополнительные регрессии проверяют границы каждого поля и кнопки внутри форм на 320/390 px, шрифт автокомплита, восстановление папки без перекрытия кнопок, модерацию тестировщиком, поздний ответ регистрации, смену проекта при задержке сети и загрузку Manrope в собранном приложении под production CSP.

Проверка неиспользуемого frontend-кода: `npm exec --yes --package=knip@5.80.2 -- knip --directory apps/web`. Конфигурация учитывает стартовый скрипт темы, CSS-импорты шрифтов/Tailwind и точки входа браузерных тестов. Перед удалением находок проверьте их фактических потребителей.

Если 4173 занят другим проектом, задайте отдельный порт, например `UCASELAB_E2E_WEB_PORT=18473 make test-ui`. Origin тестового API и адреса всех браузеров переключаются вместе; уже работающий сервер не переиспользуется.

## Панель обсуждений и черновики

`apps/web/e2e/discussion-drawer.spec.ts` проверяет немодальную панель на странице
кейса и внутри модального просмотра спецификации: взаимодействие с документом,
Escape и возврат фокуса, отдельную прокрутку и узкий экран. Вложенные формы
редактирования/модерации остаются модальными.

Неотправленные сообщения, ответы и правки хранятся только в памяти текущей
вкладки до перезагрузки. Ключ включает пользователя, проект, тип и ID объекта;
ответы и правки разделены по ветке/комментарию, сообщения — по привязке с ревизией.
Закрытие панели и переходы внутри приложения их не удаляют. Ошибка отправки
сохраняет ввод, успешная отправка очищает только отправленный текст (ввод,
изменённый во время запроса, сохраняется).

Общий черновик и черновики к фрагментам независимы. «Убрать привязку» сохраняет
текущий текст в общем поле. Если там уже был другой черновик, модальное окно
показывает оба текста: можно отменить действие без изменений либо явно объединить
их (сначала текст к фрагменту, затем общий текст после пустой строки). Исходный
черновик к фрагменту восстанавливается повторным выбором «Обсудить шаг»/
«Обсудить вариант» для того же фрагмента и ревизии. Оба пути проверяет
`apps/web/e2e/discussion-anchor-drafts.spec.ts`.

## История изменений

`activity-history.spec.ts` проверяет собственные действия как прочитанные, чужие
как лично непрочитанные, фильтры и их сброс, зависимые действия, проверку периода
и преобразование локального времени. Выбранный автор остаётся видимым при смене
проекта и ошибке периода; сброс очищает его вместе с другими условиями.
Проверка длинной истории измеряет положение
нативной полосы прокрутки у края панели, прокрутку клавиатурой и отсутствие
горизонтального переполнения на 320/390/768/1440 px в светлой и тёмной темах.
Снимки включают раскрытый период и прокрученную историю. Позднюю страницу после
смены фильтра отдельно проверяет `review-regressions.spec.ts`.

Собственные события, включая прежние записи аудита без отметок чтения, остаются
в истории и фильтре «Прочитанные», но не увеличивают счётчик непрочитанного.
Открытие панели не отмечает чужие события; чтение остаётся личным и явным.

## Черновики редакторов и адаптивность

Неотправленные кейсы и предложения сохраняются в `sessionStorage` текущей
вкладки. Ключ разделяет автора, проект, намерение редактора и стабильный ID
объекта; подготовленные пункты предложения имеют отдельные идентификаторы.
Escape, закрытие и нажатие вне окна оставляют ввод для повторного открытия
и перезагрузки в той же вкладке. Формы паролей и секретов эту политику не используют.
Успешная отправка очищает только совпадающее отправленное состояние.

Если исходные данные изменились, редактор сохраняет локальный текст отдельно
и предлагает сравнить его с текстом при открытии. Восстановление не отправляет
изменения на сервер: нужно явно сохранить черновик; проверка серверной версии
продолжает действовать. Старые ключи по названию не присваиваются объектам.

Регрессии: `ux-drafts.spec.ts` (идентичности, новая ревизия, вложенные пункты,
закрытие предложения, повреждённое хранилище), `ux-navigation-layout.spec.ts`
(URL вкладок и читаемость каталогов), `ux-editor-library.spec.ts` (длинный
редактор и заполненная мобильная библиотека), `ux-auth-links.spec.ts`
(русские ошибки ссылок и отдельная валидация пароля). Проверка режима почты
в браузере подменяет только публичную конфигурацию; фактическую обработку
валидных/истёкших ссылок и очередь почты отдельно проверяют API-тесты.

`ux-resource-readability.spec.ts` проверяет длинное название и метку спецификации
рядом с боковой навигацией и деревом папок на 768 px в обеих темах: ширину и
высоту текста, высоту строки и реальную прокрутку внутри таблицы до редактирования.
Соседние 320/390/760/1024/1440 px сохраняют читаемость и доступ к действиям.

`ux-proposal-item-identity.spec.ts` проверяет удаление одинакового подготовленного
пункта с сохранением предложения и reload: оставшийся пункт сохраняет собственный
черновик. Локальные ID связываются с подтверждённой серверной версией отдельно от
отправленного текста. После внешней ревизии или для прежних позиционных ключей
неоднозначные черновики доступны для просмотра/копирования без автоприсвоения;
чужие и неизвестные записи не показываются и не удаляются.
Старый родительский черновик с совпадающей основой сохраняет авторские поля,
но позиционные/неоднозначные ID нормализуются до открытия дочернего редактора.
Отдельно проверяются переход нового предложения к серверному ID и поздний ответ
сохранения при новом вводе после закрытия и повторного открытия.
