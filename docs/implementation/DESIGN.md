# Визуальная система и сценарии

Платформа — UCaseLab. Основная задача экрана: быстро найти функцию, понять ожидаемое поведение и увидеть достоверный результат проверки.

Палитра: чернила `#18233B`, синий `#3659E3`, фон `#F4F6FA`, граница `#E2E7F0`, успех `#187A61`, внимание `#B86719`. Красный используется только для ошибок и проваленных проверок. Синий акцент связывает выбранный проект, активный раздел и главное действие.

Типографика: локально поставляемый Manrope для заголовков и интерфейса; системный моноширинный для ключей и данных. Основной текст 14px, редактор сценария 15px с интерлиньяжем 1.65. Контраст и видимый keyboard focus обязательны.

Полноэкранная рабочая область: верхняя строка проектов, постоянная навигация, дерево папок и список. При чтении кейса дерево и список сменяются просторным документом.

```
┌ Проект ▾               Поиск                  + Создать    Уведомления  Профиль ┐
├ Навигация ┬ Папки            ┬ Юзер-кейсы / самостоятельная страница кейса      ┤
│           │ Все / архив     │ Заголовок, публикация, действие                  │
│           │ Иерархия        │ Сценарий · Проверки · Предложения · История      │
│           │                 │ Шаги → положительные / отрицательные данные      │
└───────────┴─────────────────┴──────────────────────────────────────────────────┘
```

Уходим от одинаковых карточек: основа — строки, таблицы и документ с ясной иерархией. Карточки только для самостоятельных сущностей и сводок. В интерфейсе нет демонстрационных счётчиков и фиктивных результатов. Пустой проект объясняет первое действие. Формы используют понятные поля; JSON доступен агентам, но не требуется человеку.

На узком экране навигация сворачивается, папки открываются отдельно, таблицы прокручиваются внутри области. Диалоги имеют название, Escape, перевод фокуса и возврат на исходную кнопку. Редактирование сохраняет локальный ввод при ошибках, конфликт версии требует перечитать изменения.

Роли: разработчик читает опубликованные материалы и отправляет предложения; тестировщик ведёт QA; менеджер также управляет разработчиками и тестировщиками, окружениями и настройками; руководитель владеет проектом, управляет менеджерами, передаёт владение и архивирует проект.


## Каталоги и предложения 1.1

Спецификации находятся между шагами и вариантами данных, выбираются через поиск и отображаются тегами. Теги кейсов, теги спецификаций и платформы используют независимые словари проекта с нормализацией. Поля поиска имеют клавиатурное управление, выбранные значения можно удалить, длинный каталог загружается страницами. Правый блок кейса содержит папку, приоритет, классификацию и аккаунты. Подсказка размещается рядом с действием; технические подробности скрыты в раскрываемом блоке.

Переключатель проекта — поисковый диалог с текущим выбором, ссылкой ко всем проектам и созданием нового. Логотип возвращает в юзер-кейсы выбранного проекта. Предложение начинается с намерения: новый сценарий или правка существующего. Описания достаточно; полный сценарий и источник изменения кода добавляются по желанию. Списки используют серверный поиск и URL-параметры фильтров и страниц.


## Общие заголовки и обсуждения

Обратная ссылка занимает собственную строку перед заголовком. `PageHead` содержит метаданные/статус, один основной заголовок, пояснение и группу действий. На широком экране действия выравниваются справа; длинные названия и группы переносятся без наложения, на узком экране действия занимают следующую строку. Заголовки секций используют ту же политику переноса. Каталоги сохраняют дерево, документ кейса — ширину чтения, рабочее место прогона — очередь и самостоятельную прокрутку; формы входа сохраняют отдельную композицию.

Для кейса, предложения, спецификации, отчёта и результата проверки используется один `DiscussionTrigger`: MessageSquare 19px, название/подсказка «Обсуждения», aria-haspopup/aria-expanded, выбранное состояние и видимый фокус. Вход находится в действиях соответствующего заголовка, в модальном просмотре — рядом с закрытием. Немодальная панель размещается вне заголовка, внутри родительского native dialog, если он есть: так сохраняются взаимодействие с документом, порядок Escape и возврат фокуса. Остальные страницы не получают неподдерживаемые обсуждения.

Вложенное обсуждение результата в истории кейса открывается явно и не перехватывает параметр ветки кейса. Прямые ссылки на ветки результата по-прежнему ведут в рабочее место прогона.

В отклонённом предложении доступно «Удалить» с именованным подтверждением, статусом «Удаляем…» и ошибкой внутри формы; отмена и Escape сохраняют объект. После успеха открывается список предложений. Решение и история сохраняются.
