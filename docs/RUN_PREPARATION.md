# Проверка черновиков и подготовка прогона

В «Проверках → Новая проверка» выберите опубликованные версии или текущие черновики. Кнопка «Проверить» доступна и у неопубликованного кейса. Черновик не публикуется: в прогоне остаются точная ревизия, шаги и варианты на момент подготовки. Изменения кейса после этого не меняют историю проверки. Прогоны черновиков видят тестировщики, менеджеры и руководитель; отчёты с ними автоматически доступны только этой группе.

Перед началом заполните раздел «Перед началом»: стенд открывается, аккаунты доступны, необходимые почта/CAPTCHA/инструменты работают. Это сохранённое наблюдение исполнителя, а не автоматическая сетевая проверка платформой. Пароли и коды здесь не хранятся. Адрес можно исправить в снимке прогона, не меняя настройки общего окружения.

Подготовку можно сохранить и с препятствиями. Пока готовность не подтверждена, выполнение не начнётся. Для частичного выполнения включите «Начать с ограничениями» и опишите, какую часть можно проверить. Непроверенные условия останутся непроверенными; недоступным вариантам затем нужен отдельный результат с причиной. Если связанные аккаунты изменились до начала, подтвердите подготовку заново; при изменении логина/окружения или архивации подготовьте новый прогон с актуальными связями. Старые, созданные до 1.7.0 прогоны продолжают работать без ретроспективного запрета.

## Через MCP

1. Для нового прямого запуска вызовите `preview_run(project_id,use_case_ids,case_source="draft",environment_id)`; передайте `selection_hash` в `create_run` с теми же аргументами выбора. По умолчанию источник — `published`. План использует свой `preview_case_plan` и опубликованные версии.
2. Прочитайте `get_run_readiness(project_id,run_id)`. Выполните необходимые проверки своим браузером/устройством. Аккаунты возвращаются без секретов; наличие секрета не доказывает корректность пароля. Текущий доступ к секрету определяется отдельными правами и scopes.
3. Сохраните `confirm_run_readiness` с `expected_version`, `checks={environment,accounts,dependencies}` и `notes`. Состояния: `ready`, `blocked`, `not_checked`; для аккаунтов и зависимостей также `not_required`. При необходимости укажите `actual_base_url` без пароля и параметров запроса. Частичный запуск требует `allow_partial=true` и непустой причины.
4. `begin_run_check` → реальные шаги → `finish_run_check`. Прогон выдаёт точный закреплённый вариант и ревизию. Итог неизменяем; повтор — новой попыткой. После всех результатов `complete_run`, затем `generate_report`.

У прямого запуска `selection_hash` необязателен для совместимости; если указан, изменение состава или окружения отклоняется с `RUN_SELECTION_CHANGED`. Перед стартом нового прогона отсутствие подготовки даёт `RUN_NOT_READY`. Подтверждение подготовки увеличивает версию прогона. Нельзя менять её после начала. Сервер не обращается к произвольным URL стендов и не обходит CAPTCHA.

## Как выбрать результат

| Исход | Когда использовать | Что записать |
| --- | --- | --- |
| `passed` — всё совпало | Все закреплённые шаги проверены и ожидания подтверждены, включая ожидаемый отказ | Наблюдаемый результат |
| `failed` — ошибка приложения | Ожидание подтверждено, приложение ему не соответствует | Шаг, ожидание, фактическое поведение |
| `scenario_issue` — неточность сценария | Ожидание устарело/неоднозначно, пропущены шаги или данные | Что уточнить и что удалось наблюдать |
| `blocked` — не удалось проверить | Нет доступа, аккаунта, почты, инструмента или рабочего стенда | Препятствие и границы выполненной части |
| `skipped` — пропущено | Вариант сознательно исключён из этой проверки | Причина пропуска |

Например, «тип профиля уже выбран, хотя черновик требует отсутствия выбора» — повод уточнить сценарий, пока не подтверждено, что выбор по умолчанию запрещён требованиями. Отказ соединения с ошибочно указанным доменом — препятствие проверки, а не дефект приложения.

Покрытие приложения = `(passed + failed) / selected`, доля успеха = `passed / (passed + failed)`; при нуле выполненных проверок доля успеха не определена. Неточности сценариев и препятствия учитываются отдельно. 100% сохранённых результатов означает завершённую фиксацию наблюдений, а не готовность продукта к релизу. PDF/CSV/JSON сохраняют источник, ревизию и исход; JSON также содержит полный снимок подготовки.
