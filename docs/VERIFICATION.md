# Проверка релиза 1.9.2

28 октября 2026 года. Исправления опираются на фактический прогон опубликованных сценариев UCaseLab 1.9.0: 198 вариантов, 185 passed, 6 failed, 6 blocked и 1 scenario_issue. Старый отчёт неизменяем и не исправляется задним числом. Предыдущая проверка приложения сохранена в [истории 1.9.0](verification/1.9.0.md).

Исправлены все шесть подтверждённых дефектов: пустая причина раскрытия пароля, недостаточные права тестировщика на модерацию, активация плана с пустым/недоступным набором вариантов, переполнение форм на 320 px, непонятная ошибка отозванного MCP-токена и нестабильный формат ошибок аргументов MCP. Для модерации добавлена кнопка с обязательной причиной в интерфейсе; исходный текст и аудит сохраняются.

Дополнительно исправлены: загрузка Manrope под строгой CSP, поздний ответ регистрации после перехода ко входу, действия предыдущего проекта во время загрузки нового, автоматическое раскрытие выбора родительской папки поверх кнопки восстановления, мелкий текст автокомплита и редактора параметров и узкая сетка редактора шагов/параметров. Формы спецификации и тестового аккаунта используют общий подвал с явной отменой. Для незавершённого выбора вариантов плана появилась подсказка о сохранении черновика. Токен с полностью пустым списком scopes по-прежнему отклоняется; ошибочные входные данные такого сценария исправлены в машинном каталоге.

Проверки:

- 136 pytest-тестов, комбинированное покрытие строк и ветвей 89%. Новые регрессии включают Unicode-пробелы в причине, отсутствие события раскрытия при отказе, четыре роли модерации, сохранность истории/аудита, создание и изменение активных планов, дубли/удалённые/отключённые варианты и закреплённую публикацию вместо рабочего черновика.
- Официальный MCP SDK проверяет транспорт целиком: initialize, вызов с неизвестным полем, JSON VALIDATION_ERROR без входных значений и повторный вызов после отзыва с UNAUTHENTICATED. Схемы и REST используют тот же реестр из 136 операций.
- 96 браузерных проверок прошли без повторов и пропусков: Chromium desktop/mobile, WebKit, Firefox smoke. Проверяется собранный frontend через Vite preview с настоящими заголовками из nginx-конфига. Включены формы 320/390 px, геометрия каждого поля/кнопки, шрифты под CSP, роль тестировщика, восстановление папки и задержки ответов регистрации/переключения проектов. Остальная регрессия охватывает кейсы, требования, аккаунты, планы, готовность, выполнение, отчёты, роли, уведомления, темы и доступность axe.
- Ruff, mypy (26 модулей), TypeScript strict и типы UI-тестов; проверка ссылок/схем документации и девяти ZIP навыков. Docker web build проходит. Knip не находит неиспользуемых файлов, экспортов или зависимостей; удалены четыре ненужных экспорта типов/локальных вспомогательных объектов.
- Все миграции на новой схеме: 38 таблиц, без расхождения модели и БД. Конкурентные записи сохраняют уникальные номера кейсов и единственного владельца проекта. Новая миграция для 1.9.2 не требуется.

Локальные артефакты: `output/pytest-fixes.log`, `output/ui-full-fixes.log`, `output/playwright/e2e`, `output/migrations-fixes.log`, `output/docker-build-fixes.log`. Результаты серверной проверки фиксируются в отчёте UCaseLab и журнале развёртывания.

Границы: реальная внешняя почта остаётся выключена по решению владельца; физические телефоны, CAPTCHA и нагрузочные лимиты на production не испытываются. Browser emulation и автоматические тесты не доказывают отсутствие всех возможных ошибок. Исторические blocked-проверки требуют соответствующего стенда, а не смены статуса на passed.
