# Проверка релиза 1.5.0

Проверено 27 октября 2026 года. Предыдущие проверки: [1.4.0](1.4.0.md), [1.3.0](1.3.0.md).

Доработано управление папками: создание подпапок, переименование, перемещение ветки в диалоге и перетаскиванием, порядок среди соседей, сворачивание дерева, поиск по полному пути и хлебные крошки. В библиотеке можно включать кейсы из подпапок. Выбор папки в редакторе и на мобильном экране использует поиск с пагинацией.

Удаление сохраняет содержимое: прямые кейсы, включая архивные, и активные подпапки перемещаются на уровень выше, в корень либо выбранную папку. История, публикации и результаты остаются неизменными. Удалённый контейнер можно восстановить отдельно; ранее перенесённое содержимое остаётся на месте.

- `uv run --frozen pytest -q`: **54 passed**, PostgreSQL. Новые проверки охватывают пути/поиск/пагинацию, вложенную фильтрацию, порядок, перенос ветки, циклы, предел 32 уровней, конфликты версий, межпроектную изоляцию, права разработчика, непустое удаление, архивные кейсы, сохранность ревизий/публикаций и восстановление. Отдельный тест проходит жизненный цикл и повтор удаления через MCP transport.
- `uv run ruff check apps/api`, TypeScript и Vite production build проходят.
- Реальный браузер Playwright, отдельный локальный QA-проект: создание трёх уровней, переименование без смены родителя, сворачивание, диалог перемещения в корень, перетаскивание обратно в родителя, поиск по пути, переключение вложенных кейсов, удаление папки с кейсом и подпапкой, проверка оставшихся кейсов, восстановление пустого контейнера, изменение порядка, клавиатурное меню и поиск папки в редакторе кейса.
- Мобильный экран 390×844: выбор папки по пути и перемещение через диалог; горизонтального переполнения нет. Снимки: `output/playwright/folders-{tree,delete,mobile}.png`.
- Экспортирован контракт **119 MCP-инструментов**. Добавлены get_folder, rename_folder, move_folder, delete_folder, restore_folder; прежний archive_folder сохранён. Все схемы проверяются общим тестом каталога. Семь пакетов навыков 1.5.0 проверены по содержимому, ссылкам, инструментам и SHA-256. В навыках описан процесс управления папками.

Схема БД не менялась: используются существующие parent_id, position, version и archived. Проверки concurrency/идемпотентности работают через общую границу REST/MCP. Нагрузочные испытания на больших деревьях не проводились. Результаты проверки после развёртывания и резервная копия фиксируются в журнале эксплуатации сервера.
