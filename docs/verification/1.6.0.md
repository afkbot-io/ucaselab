# Подготовка релиза 1.6.0

Проверено 27 октября 2026 года. **Релиз подготовлен локально; на сервер не выгружался.** Предыдущая проверка: [1.5.0](1.5.0.md).

## Изменения

- Независимые папки спецификаций: дерево, подпапки, поиск по пути, сворачивание, перемещение ветки и порядок соседей. Удаление контейнера переносит также архивные спецификации и сохраняет историю/связи; контейнер можно восстановить отдельно.
- Спецификации: CRUD с явными delete/restore, перемещение без новой ревизии, сохранение папки при обычном редактировании, отсутствие пустых ревизий для неизменённого содержимого, история с пагинацией, чтение конкретной ревизии.
- set_use_case_specifications меняет только связи и возвращает полный кейс. Существующие архивные ссылки сохраняются при редактировании, новые требуют восстановления спецификации. В UI ссылка из кейса открывает закреплённую ревизию; актуальная версия доступна отдельным действием.
- «MCP и навыки» работает внутри `/p/:projectId/profile` с прежним проектом и меню. `/profile` направляет в последний доступный выбранный проект. Токен по умолчанию ограничен текущим проектом; инструкции показываются для него. Добавлен набор разрешений «Предложения».
- Новые навыки ucaselab-review-proposals и ucaselab-apply-proposals. prepare_proposal позволяет QA подготовить открытое предложение другого автора, не меняя автора, описание и источник. preview и принятие остаются отдельными; применение создаёт черновики.
- Исправлен экспорт проекта через MCP: устаревший импорт папок, усечение каталогов первой страницей. Экспорт содержит независимое дерево спецификаций и текущие/закреплённые снимки, включая архивные связанные требования. Секреты аккаунтов в экспорт не входят.

## Проверки

- `uv run --frozen pytest -q`: **62 passed** на PostgreSQL. Покрыты независимость папок/проектов, права и scopes, CRUD и ревизии спецификаций, неверные/дублирующиеся связи, сохранение опубликованной версии, редактирование с архивными связями, подготовка чужого предложения QA, preview/применение/идемпотентность и экспорт.
- Общая проверка каталога валидирует **132 MCP-схемы**, строгие аргументы и annotations. Отдельные wire-тесты проходят жизненный цикл спецификации, закрепление и восстановление, подготовку и применение предложения.
- Официальный MCP SDK обращался к локальному HTTP endpoint `/mcp/`. Выполнены создание папок и спецификации, повтор создания с одним ключом, редактирование с сохранением папки, связывание с кейсом, чтение исходной ревизии после обновления, фильтрация вложенных спецификаций, удаление/восстановление/перемещение, редактирование кейса после архивирования требования и запрет новых архивных связей. Проверено сохранение ID публикации.
- Отдельный developer credential отправил идею и получил отказ на подготовку; QA подготовил предложение с сохранением автора/описания, увидел diff и применил его в новый черновик. Повтор принятия не создал дубль. Следующее предложение изменило существующий кейс без публикации. Возвращённые decision.applied_items проверены чтением кейсов.
- Девять Markdown/ZIP скачаны через MCP-каталог и сопоставлены по содержимому и SHA-256. scripts/check_skills.py и quick_validate.py для двух новых навыков проходят. Модельное A/B-сравнение не проводилось; проверялся реальный инструментальный процесс.
- Playwright: создание папки и подпапки спецификаций, создание/редактирование требования с тегом, перенос в родителя через поиск, вложенный фильтр, удаление непустой папки с сохранением спецификации, удаление и восстановление требования. Закреплённая ревизия из кейса показывает исходный текст, переход к текущей версии — новый текст. В профиле сохранён проект/боковое меню, обновление страницы и `/profile` не сбрасывают выбор; девять карточек, один guide и текущий проект в форме токена.
- Мобильный экран 390×844: выбор папки по пути, отсутствие папок спецификаций в выборе папки кейса, читаемые строки и отсутствие горизонтального переполнения. Снимки: `output/playwright/specifications-{folders,pinned,profile,mobile}.png`.
- Ruff и TypeScript/Vite production build проходят.
- scripts/check_migrations.py: чистая схема, **38 таблиц**, без расхождений модели/схемы; конкурентные записи сохраняют уникальные номера кейсов и единственного владельца проекта.

## Развёртывание и ограничения

Миграция 0003_specification_folders добавляет folders.kind (существующие папки — use_cases), specifications.folder_id и индексы/ограничения. Идентификаторы и содержимое существующих ревизий не заменяются. Она применена только к локальной базе. Перед будущей выкладкой нужна согласованная резервная копия; возврат к 1.5 после создания папок спецификаций требует восстановления БД, а не только замены приложения. См. [DEPLOYMENT.md](../DEPLOYMENT.md).

Проверки выполнялись в отдельном локальном QA-проекте. Исходные проекты/прогон не использовались для тестовых записей. Служебный проект архивирован, два временных MCP-токена отозваны с подтверждённым HTTP 401, тестовая браузерная сессия удалена. Исходный локальный прогон остаётся running, 0/2. Серверные контейнеры, nginx и данные не менялись. Docker-образы этого релиза и нагрузка на очень больших деревьях отдельно не проверялись; подтверждены backend, миграции, Vite build, интерфейс и MCP в локальной среде.
