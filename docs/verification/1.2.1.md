# Проверка релиза 1.2.1

Проверено 26 октября 2026 года на локальном Docker Compose с PostgreSQL 17 и Mailpit. На внешнем сервере релиз не развёртывался. Предыдущие проверки платформы и восстановления описаны в [истории 1.1](1.1.md).

## Изменения

Раздел проверок переработан вокруг трёх этапов: подготовка, выполнение, результаты. Слева — постраничная очередь вариантов с поиском и фильтрами, справа — один закреплённый вариант: данные, ожидаемое поведение и шаги. Итог явно выбирается в отдельном диалоге; успешный результат не выбран заранее. Прогресс считает сохранённые результаты, включая расхождения, блокировки и пропуски. Следующий вариант после сохранения открывается для просмотра и не начинается автоматически. Закрытие прогона — отдельное действие.

Добавлены пять общих REST/MCP операций: get_run_overview, list_run_checks, get_run_check, begin_run_check, finish_run_check. Обзор и очередь не передают все снимки. Начало учитывает назначение, свою активную проверку и занятые общие аккаунты; итог со шагами сохраняется атомарно. Для passed все закреплённые шаги должны быть passed. Ответ возвращает next_action с точным следующим вызовом. Прежние низкоуровневые операции сохранены для совместимости.

## Автоматические проверки

- `uv run ruff check apps/api` — успешно.
- `uv run pytest -q` — **35 passed** на PostgreSQL. Шесть новых тестов проверяют начало/продолжение, отсутствие неявного начала следующего варианта, полноту шагов и атомарный отказ, историю повторов, назначение/права исполнителя, изоляцию проектов, страницы очереди, ожидание занятого аккаунта и отсутствие старта при недоступных проверках.
- TypeScript и production-сборка Vite проходят, контейнерные образы собираются.
- 114 операций экспортированы в API_SCHEMA.json; семь навыков обновлены до 1.2.0, включая рекомендуемый процесс выполнения.
- `uv run python scripts/check_migrations.py` — новая временная схема, 38 таблиц, расхождений с моделями нет; проверены параллельная нумерация кейсов и единственный владелец проекта.
- Семь ZIP навыков проверены quick_validate, CRC, SHA-256 и сравнением с исходниками.
- Модель БД не изменялась: миграции 0001/0002 и 38 таблиц сохраняются. Новая миграция для обновления 1.1 → 1.2 не требуется.

## Реальный интерфейс

В отдельном QA-проекте через интерфейс создан подготовленный прогон из опубликованного кейса с двумя вариантами. Проверены явное начало, отсутствие предвыбранного итога, недоступность успеха до отметок шагов, сохранение фактического наблюдения и загрузка скриншота. После первого результата второй вариант остался в ожидании. После всех результатов явно завершён прогон и создан неизменяемый отчёт с обоими наблюдениями.

Экран визуально проверен при 1440×1000 и 390×844. На мобильном проверена кнопка очереди, возврат к варианту, отметки шагов и диалог итога. Найден и исправлен выход длинного названия проекта за ширину экрана; после исправления scrollWidth равен innerWidth, 390 px. Локальные скриншоты сохранены в output/playwright и не включены в исходный архив. Существующий активный прогон пользователя не выполнялся и не закрывался.

## MCP на работающем приложении

Официальным SDK выполнены initialize и tools/list (114 инструментов), чтение контекста 1.2.0, создание прогона, начало и повторное получение той же попытки. Запись passed без шагов вернула STEPS_INCOMPLETE; последующее чтение подтвердило отсутствие частичной записи. Полный результат со шагами сохранён атомарно, next_action предложил завершение, прогон завершён. Проверены страницы очереди по одной записи и отсутствие snapshot в индексной выдаче. Временный токен отозван.

В исходный демонстрационный проект отправлено открытое предложение нового юзер-кейса по процессу выполнения и MCP с отпечатком изменения исходников относительно релиза 1.1. До принятия новый кейс не создавался. Инструкция проекта обновлена до нового процесса. Отдельный QA-проект после проверки архивирован; текущий прогон пользователя остался running с 0 из 2 записанных результатов.

## Границы

Платформа сама не запускает браузер или мобильное устройство. Проверяющий человек или агент выполняет реальные действия и сохраняет наблюдения. Новый helper требует полноты шагов для passed; прежний record_execution_result сохранён без изменения контракта. Автообновление активного экрана — опрос каждые пять секунд при видимой вкладке. Нагрузочное испытание, формальный аудит доступности и удалённый CI в этом обновлении не выполнялись.

## Дополнение 1.2.1: установка без почты

Новый тест проверяет регистрацию без подтверждения, вход, отсутствие новых email challenges и писем, отказ email endpoints, сохранение прежнего пароля при повторной регистрации и приглашение ссылкой. EMAIL_ENABLED по умолчанию true, существующий режим с письмами сохранён. В интерфейсе скрываются недоступные почтовые действия.
