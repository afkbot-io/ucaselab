## 2. Механизм загрузки в продукте

В профиле работает раздел «Навыки для агента»: описание, версия, назначение, архив и контрольная сумма. Тот же каталог доступен агенту через `list_skills` и `get_skill(name)`.

`get_skill` возвращает Markdown и `download_path`: `/api/skills/{archive}`. ZIP скачивается из профиля или по этому защищённому пути с аутентификацией. Имена архивов и SHA-256 определяет текущий манифест.

Общие навыки можно раздавать без проектных данных. Проектный guide содержит закрытый контекст и доступен с аутентификацией. Настоящие токены, пароли, закрытые URL с credentials и индивидуальные аккаунты в ZIP не входят.

Skill не является исполняемым runner, не устанавливает Playwright/Appium, не создаёт MCP-подключение и не выдаёт scopes. Он описывает процесс использования уже подключённых инструментов. Разные клиенты поддерживают собственные способы установки; при отсутствии поддержки skills агент может прочитать тот же Markdown явно.

## 3. Версии и совместимость

Сервер сообщает `contract_version` и capabilities в `get_project_context`. Агент сверяет их до записи. Если возможности отсутствуют, он сообщает ограничение и может подготовить локальный черновик, но не утверждает об успешной серверной операции.

Опубликованный архив одной версии неизменяем. При изменении инструкций выпускается новая версия; проект не обновляет навыки молча. Манифест содержит имя, описание, версию, контракт, путь архива, размер, точку входа и SHA-256.

Новые инструменты могут требовать нового навыка или обновления пакета. Подпись каталога/релизов можно добавить позже; сейчас предусмотрена проверка целостности хешем, которая сама по себе не удостоверяет доверенность источника.

## 4. Пересборка

```sh
python3 scripts/package_skills.py
python3 scripts/check_skills.py
```

Скрипт использует стандартную библиотеку Python, создаёт детерминированные архивы в одной среде и обновляет [index.json](../dist/skills/index.json). Скрытые файлы и симлинки отвергаются. Пакетировщик читает используемые в исходниках однострочные scalar-поля frontmatter; совпадение метаданных, ссылок на инструменты и ZIP проверяет `scripts/check_skills.py`.

Перед выдачей проверяются frontmatter, имена, ссылки на существующие инструменты контракта, содержимое ZIP и соответствие SHA-256 манифесту. Чтение каталога и навыков проверено на работающем сервере официальным MCP SDK.

## 5. Подключение к разработке

Для связанного репозитория проектный guide и инструкции разработки указывают `project_id`, repository key и необходимость `ucaselab-propose-changes` после завершённого набора изменений backend/frontend. Навык описывает процесс агента; фактические права и версии проверяет [MCP-контракт](MCP_CONTRACT.md). CI приложения выполняет проверки из [TESTING.md](TESTING.md), но сам по себе не подтверждает отправку предложения внешним агентом.

Роли проекта — Разработчик, Тестировщик, Менеджер, Руководитель-владелец. Разработчик-агент может иметь чтение, предложения и комментарии. Тестирующий агент — чтение публикаций и запись результатов, с отдельным доступом к секретам при необходимости. Тестировщик ведёт весь QA-процесс, Менеджер дополнительно управляет настройками и разработчиками/тестировщиками, а Руководитель владеет проектом. Навык выбирает процесс, а сервер обеспечивает эти границы.

Поведенческие сценарии для проверки агента собраны в [evals/skills.jsonl](evals/skills.jsonl). Они задают ожидаемые результаты, но не являются уже проведённым модельным A/B-тестом.


## Одна ссылка для подключения ИИ

В профиле на вкладке «Навыки для агента» скопируйте ссылку `/ai.md` и отправьте её агенту. Это публичная Markdown-инструкция с MCP endpoint, выбором процесса и ссылками на девять навыков. Агент может прочитать SKILL.md без установки или скачать только нужные ZIP. `/api/agent/manifest` возвращает версии, SHA-256, размеры, read_url и download_url. Ссылка стабильна при обновлениях приложения.

Публично доступны только материалы релиза. Пользовательские инструкции проектов, их названия, участники, результаты и токены туда не включаются. MCP-токен пользователь передаёт отдельно через настройки клиента. Guide проекта агент читает через авторизованный MCP get_project_context/get_project_guide; прежний защищённый маршрут `/api/projects/{id}/ai.md` сохраняется.

## Проверка процесса рассмотрения предложений

Навык аудита не применяет изменения сам по себе. Навык применения использует prepare_proposal для подготовки открытого предложения любого автора с ролью QA; описание и автор сохраняются. Затем preview_proposal показывает разницу, accept_proposal создаёт/обновляет черновики. Повтор точного запроса с idempotency_key не создаёт дубликат. Закрытое предложение сначала проверяется по decision.applied_items.

В 1.6 процесс проверен официальным MCP-клиентом на отдельном локальном проекте: разработчик отправляет идею, QA подготавливает и принимает её, затем изменяет существующий кейс через следующее предложение. Проверено сохранение автора, исходного описания, отсутствие кейса до принятия, возвращённые use_case_id/revision_id и отсутствие автоматической публикации. Отдельный модельный A/B-тест новых навыков не проводился.
