# Предложение для QA

Используй выбранный проект и его guide. Для порученного изменения связанного backend/frontend отправь одно предложение на завершённый набор изменений, если это требуется правилами проекта. Не создавай предложения для посторонних репозиториев, каждого файла или промежуточного шага. Простое чтение и проверка без правки кода не требуют предложения об изменении.

## Намерение

- kind=new_use_case — предложить новый сценарий, без target_use_case_id. Не вызывай create_use_case заранее.
- kind=update_use_case — правка: target_use_case_id либо items с use_case_id/base_revision_id. Найди нужный кейс точным ID или коротким поиском.

Достаточно content.description: что изменилось для пользователя, какие ожидания нужно закрепить и что реально проверено. Полный сценарий в items необязателен. Не выдумывай требования или результаты ради заполнения полей.

Для изменения кода приложи repository и полный commit_sha (40/64 hex) либо diff_fingerprint рабочего изменения; impact — behavior_changed/no_behavior_change/unknown. При no_behavior_change объясни почему. После коммита проверка конкретного SHA не заменяется прежним отпечатком diff. check_change_proposals позволяет найти уже отправленное предложение и не дублировать его.

## Подготовленные пункты и решение

items: note; create_use_case с полным content и необязательной folder_id; update_use_case с use_case_id, base_revision_id и полным content. Один кейс меняется одним пунктом. Стабильные ключи строк сохраняются.

Автор обновляет open-предложение через update_proposal с expected_version. QA использует preview_proposal, проверяет diff/конфликты и принимает или отклоняет в рамках поручения. accept_proposal применяет весь набор в черновики атомарно; при PROPOSAL_BASE_CONFLICT перечитай базы и пересобери предложение. Принятие идеи без items не создаёт кейс. Публикация и проверка приложения — отдельные действия.

Если сервер недоступен, сохрани безопасный локальный черновик и явно сообщи об отсутствии отправки. Не повторяй внешнюю запись без проверки результата; idempotency_key поддерживает повтор точного запроса. Не включай credentials в описание, кодовую ссылку или diff.
