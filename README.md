# UCaseLab

UCaseLab хранит юзер-кейсы, их версии и результаты проверок в самостоятельно развёртываемом веб-приложении с MCP-доступом для агентов.

Стек: FastAPI, SQLAlchemy/Alembic, PostgreSQL 17, React/TypeScript, Vite, Tailwind CSS и Python MCP SDK. Зависимости закреплены в `uv.lock` и `apps/web/package-lock.json`.

## Возможности

- Юзер-кейсы со шагами, ожиданиями, положительными и отрицательными вариантами данных; папки и связанные спецификации.
- Черновики, опубликованные версии, сравнение изменений, предложения и обсуждения.
- Планы и прогоны с подготовкой доступов, наблюдениями, доказательствами и отчётами PDF/CSV/JSON. Внешнюю задачу можно связать ссылкой.
- Проекты с четырьмя ролями, окружения и зашифрованные тестовые аккаунты.

## Быстрый старт

Для новой локальной копии нужны Git, Docker с Compose v2 и Python 3.12–3.14:

```bash
git clone https://github.com/afkbot-io/ucaselab.git
cd ucaselab
python3 scripts/init_env.py
python3 scripts/package_skills.py
docker compose -f compose.yaml -f compose.dev.yaml -f compose.local.yaml up -d --build
```

`init_env.py` создаёт `.env` с уникальными ключами и правами 0600; существующий файл не перезаписывает. Не добавляйте `.env` в Git. Для существующей установки следуйте [порядку обновления](docs/DEPLOYMENT.md#обновление).

Откройте http://localhost:8080, зарегистрируйтесь и подтвердите адрес через локальную почту Mailpit на http://localhost:8029. Создайте проект: его создатель становится руководителем. Демонстрационные данные не добавляются, письма остаются в Mailpit. Готовность API: http://localhost:8080/api/health/ready.

## Развёртывание

Установка на Linux с HTTPS и основным `compose.yaml` описана в [руководстве развёртывания](docs/DEPLOYMENT.md). Настройте SMTP либо задайте `EMAIL_ENABLED=false`: без почты доступен вход по паролю, ссылки восстановления не отправляются.

Сохраняйте `.env`, пароль БД, `SECRET_KEY` и `ENCRYPTION_KEY` вне репозитория. Перед обновлением подготовьте [резервную копию и проверьте порядок восстановления](docs/DEPLOYMENT.md#резервное-копирование): копия содержит БД, вложения и секретный `environment.env`, ей нужно закрытое хранение. Прежние ключи нужны для восстановления; `docker compose down -v` удаляет данные.

## Разработка и проверки

Из корня локальной копии сгенерируйте `.env`, если его ещё нет, и установите зависимости:

```bash
python3 scripts/init_env.py
uv sync --frozen --python 3.13
make dev-db
make migrate
npm ci --prefix apps/web
```

При существующем `.env` пропустите первую команду и проверьте локальные настройки. В отдельных терминалах запустите `make api`, `make worker` и `make web`. Интерфейс: http://localhost:5173, API: http://127.0.0.1:8017, Mailpit: http://localhost:8029. Порты БД и SMTP — 54329 и 10259.

- `make test` — тесты, линтеры, типы, документация и сборка.
- `make test-ui` — браузерные проверки Playwright.
- `make test-all` — обе группы.

Используйте отдельный локальный PostgreSQL с применёнными миграциями, без рабочих данных. Подготовка, состав проверок, браузерная матрица и отчёты — в [TESTING.md](docs/TESTING.md); выполненные проверки и их ограничения — в [VERIFICATION.md](docs/VERIFICATION.md).

## Документация

Для агента создайте токен в профиле → «MCP-доступ»: endpoint `https://ваш-домен/mcp/`, транспорт Streamable HTTP, заголовок `Authorization: Bearer …`. Токен показывается один раз. Передайте агенту `https://ваш-домен/ai.md` с каталогом девяти навыков; токен и инструкции проекта выдаются отдельно с проверкой доступа. Навыки также скачиваются в профиле. Агент выполняет действия собственным браузером, устройством или API-инструментами, а платформа сохраняет сценарии и результаты.
